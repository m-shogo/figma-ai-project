# 受入条件・テスト計画

Status: Codex接続済みChrome経由の単発送信を観測済み。拡張経由の送信・定期運用は未検証、無効。

## Gate 0 — 利用条件と環境

- 最新Human指示により、明示的許容の確認待ち・問い合わせを実装の前提にしない。禁止事項・認証・利用枠・保護措置は遵守する。拡張インストール・サイト権限は実行直前の承認を得る。
- 端末ごとのブラウザ/OS/セキュリティ更新、電源・ネットワーク、ログイン状態を実機で確認。
- 高性能モデルの利用枠に従い、上限・認証・安全チェックが出たら停止。回避や自動再認証は行わない。
- 追加費用の発生を許可しない。電気代・既存契約利用量は別途把握する。

## Gate 1 — オフラインの模擬UIによるテスト

実サービスへの送信なしで状態管理・誤操作防止・機種別アダプターを検証する。

- 正しいチャット／誤ったチャット／チャットが見つからない。
- Figma選択済み／未選択／選択不明。文字列やリンクだけをプラグイン選択の証拠にしない。
- 空の入力欄／人の下書きがある／送信できない。
- IDLE / BUSY / UNKNOWN / LIMIT / AUTH_REQUIRED / OFFLINE / DISABLED。
- 二重起動、スリープ復帰、日付変更、タイムアウト、送信結果不明、突然のUI変更。
- UNKNOWNや送信結果不明の場合は再送しない。異常時は停止・通知・原因記録。人の入力や別チャットを上書きしない。
- 異なる端末同士の同時起動も禁止。初期運用は片方のみ。端末切替は明示的な引継ぎを必要とする。

## Gate 2 — 本人操作による実機確認

- 既存チャットで本物のFigma選択を確認し、「慎重に進んで」の本人による送信で期待したskill・Figma取得が実際に成功することを確認。
- 実装・GitHub・WordPressの成功と、単なるメッセージ送信成功を区別。
- 各端末で成功/失敗、ブラウザのバージョン、状態判定根拠を記録。
- 個人情報、認証情報、出力本文の自動収集はしない。

## Gate 3 — 許容される実運用

最新Human指示に従い、本人管理下で単発の送信、重複防止、異常時停止を検証する。正式許諾を取得済みとは報告しない。新たな権限の付与と本運用切替は別途実行直前に承認を得る。

最終受入: 設定した間隔で、真正なFigma選択と指定のメッセージ送信が人手なしで成功し、実行中・上限・認証・異常時は誤送信せず停止/スキップすること。複数回の実機再現で評価する。単発の成功やローカルタイマーの起動だけでは完成でない。実際の実装進捗と品質はGitHubのcommit/PR/CIと案件QAで確認する。既存定期タスクとの並行実装はさせない。
