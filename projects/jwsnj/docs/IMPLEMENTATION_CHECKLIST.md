Human 指示（2026-11-20）に基づく案件固有のチェックシート。各作業単位で着手前・実装中・コミット前・マージ前・完了後に確認する。共通正本は `docs/frontend-quick-contract.md`、`docs/agent-human-fb-weak-spots.md`、`docs/css-strategy.md`。既存の品質ゲートや project guard を置き換えない。

記録方法: 各項目は PASS / FAIL / 未検証 / N/A（理由付き）で判定し、該当する検証ログ・スクリーンショット・コミット・PRへの参照を作業記録に残す。未検証をPASSとして扱わない。

- [ ] Figma由来アセットを本物の素材で管理し、仮の画像・文言・URLが本番表示されないようにする。フォント・アイコンの提供/ライセンスを確認する

## 実装中
- [ ] 通常コンテンツは文書フロー・Flex・Grid等で組み、意図しない `position:absolute` / `height` でレイアウトを固定しない。装飾・意図的な重なりは例外可。**jwsnjの新規実装では `white-space: nowrap` は禁止**
- [ ] **通常テキストに `line-height: 1`（100%）を残さず、原則 `1.3`（単位なし）にする**。単体アイコンglyph等、必要な例外は理由を記録する
- [ ] 見出し、ボタン、ナビ、カードの文字列を2〜3行にした場合、行の重なり・周囲の余白・隣接要素・クリック領域が崩れない
- [ ] PC/SPと中間幅・長い日本語/英語混在文言・CMSの可変テキスト・フォント差を想定し、`height` / `min-height` / `overflow` / `flex-shrink` などを確認する。**150〜200%文字拡大の専用テストは不要**
- [ ] 使用アセットと実装位置・サイズを確認。ナビは **PC hover / SP click・tap** を主動作として操作検証。既存のfocus・keyboard操作を破壊しない
- [ ] 既存のWordPress/ACFとThemeの書き方に合わせ、未承認のfield・slug・ダミー文言を創作しない

## コミット・push前
- [ ] スコープ外の差分や整形が混入していないかセルフレビューする
- [ ] `line-height:1` / `100%` の通常テキストと、固定高/折り返し不可の指定がないか（通常テキストへの `white-space: nowrap` は使用不可）変更箇所と関連部品を検索する
- [ ] 実行可能な構文・ビルド・静的チェックを実行し、結果を保存する
- [ ] 実行可能なら実機で2行・3行、PC/SP・中間幅、hover・open/close、横スクロール、共通部品の回帰を確認する

## PR・soへのマージ前後
- [ ] PR差分、CI結果、競合、対象SHA、他の作業との整合性を確認する
- [ ] 未解決の重大な差分を残したままマージしない
- [ ] マージ後に `so` を再取得して反映を確認する
- [ ] 今回発見したミス・見逃した理由・再発防止・検証を `LEARNINGS.md` とチェック項目へ反映し、次回の作業単位を明示する

## テキスト行間の判断例
- 通常の本文・見出し・ナビ・ボタン：`line-height: 1` と指定されていたら原則 `line-height: 1.3` にする
- アイコンフォントや装飾のみ：必要なら `1` を維持可能。ただし文章テキストへの流用はしない
- Figmaとの差異：単一行の高さだけで合わせず、複数行やレスポンシブでの自然な伸びを優先し、実測して説明する
