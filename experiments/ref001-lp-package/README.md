# 千葉経済大学 LP パッケージ

`lp-originalPage.php` と `lp/` フォルダをテーマ直下にコピーするだけで動く、
自己完結型の LP です。

- まずは **ACF なし** の直書き状態でそのまま公開できます
- あとから **学生の声 / スライダーの2箇所だけ** を ACF PRO で編集可能にできます

---

## 1. 何がどこにあるか

```
lp-originalPage.php   ページ本体。全セクションが見た目どおりの順で直書きしてあります。
                       （REF-001 自身の Header / Footer も含みます）
lp/
├── css/ref001.css                スタイル（このLP専用。1ファイル）
├── js/ref001-interactions.js     アコーディオン / スライダー / ページトップ
├── image/
│   ├── icons/*.svg                アイコン
│   ├── mv/*.svg                   メインビジュアルのあしらい
│   ├── backgrounds/*.jpg          CTA の背景写真
│   └── photos/{pc,sp}/*.webp      写真（PC用 / SP用）
├── acf-swap/                      ACF で編集したくなったときだけ使うファイル
│   ├── _helpers.php
│   ├── student-voice-acf.php
│   └── swiper-acf.php
├── acf-json/                      ACF PRO のフィールド定義（Local JSON）
│   ├── group_ref001_student_voice.json
│   └── group_ref001_swiper.json
└── acf-export.json                上2つをまとめた確認用ファイル
```

---

## 2. 設置手順（ACF なし）

1. `lp-originalPage.php` と `lp/` をテーマのルート直下にコピーする
2. 管理画面で固定ページを作り、テンプレートに
   **「LP オリジナルページ」** を選ぶ
3. 以上。ACF PRO は不要です

文言や画像を変えたいときは `lp-originalPage.php` を直接編集してください。
セクションごとにコメントで区切ってあります。

---

## 3. あとから ACF で編集できるようにする

1. ACF PRO を有効化する（`lp/acf-json/` は自動で読み込まれます）
2. `lp-originalPage.php` の中の該当セクションを、丸ごと include に置き換える

   学生の声 … `<section class="p-voice"> 〜 </section>` を:
   ```php
   <?php include __DIR__ . '/lp/acf-swap/student-voice-acf.php'; ?>
   ```
   スライダー … `<section class="p-messages"> 〜 </section>` を:
   ```php
   <?php include __DIR__ . '/lp/acf-swap/swiper-acf.php'; ?>
   ```
3. 管理画面の繰り返しフィールドで編集する
   - 学生の声 … `ref001_student_voices`
   - スライダー … `ref001_swiper_slides`

フィールドを空にしたまま／ACF を止めた場合でも、直書き版と同じ内容が
表示されます（PHP の警告も出ません）。
スライダーは枚数を増減すると、右下のカウンター（1 ── 4）も自動で追従します。

## 4. 設計の考え方（なぜこう書いたか）

### 4-1. HTML の構造

```html
<body class="p-lp">
  <header class="p-header"> … </header>
  <main class="l-main">
    <section class="p-mv"> … </section>
    <section class="p-reason"> … </section>
    …
  </main>
  <footer class="p-footer"> … </footer>
</body>
```

**なぜ 1セクション = 1 `<section>` + 1クラス にしたか**

- 画面で見えている「かたまり」と、HTML の `<section>` と、CSS のブロックが
  **1対1**になります。直したい場所を画面で見つけたら、そのままファイル内を
  検索すれば当たります。探し回る必要がありません。
- `<header>` `<main>` `<footer>` `<section>` `<nav>` を使い、`<div>` は
  「見た目のためだけの入れ物」に限定しています。読み上げソフトや検索エンジンが
  ページの構造を正しく理解できます。
- 見出しは `<h1>`（メインビジュアル）→ `<h2>`（各セクション）→ `<h3>`（カード）と
  飛ばさずに下げています。

**繰り返しは同じ形にそろえる**

コース7枚・学びの4ステップ・学生の声3件は、すべて同じ入れ子の形にしてあります。
1件コピーして中身を書き換えれば増やせます。CSS を足す必要はありません。

### 4-2. クラスの名前

FLOCSS という考え方をベースにした3階層です。**接頭辞を見れば、その指定が
どこまで影響するかが分かる**ようにしています。

| 接頭辞 | 意味 | 影響範囲 | 例 |
| --- | --- | --- | --- |
| `l-` | レイアウトの入れ物 | ページ全体 | `l-container` |
| `c-` | 使い回すパーツ | 複数セクション | `c-btn` `c-kicker` `c-heading` `c-checklist` |
| `p-` | ページのセクション | そのセクションだけ | `p-mv` `p-reason` `p-courses` |

その中は BEM（`ブロック__要素--状態`）です。

```
p-reason__card          REASON セクションのカード
p-messages__arrow--prev MESSAGES セクションの矢印（前へ）
is-open                 開いている状態（状態だけは is- で表す）
```

**なぜこうしたか**

- `p-reason` で検索すると **そのセクションのCSSだけ**が出ます。
  `card` や `title` のような一般的な単語で検索して大量にヒットする、
  という状態を避けられます。
- 名前を見た瞬間に「これを直すと他に影響するか」が判断できます。
  `c-btn` を触ると全ボタンに響く／`p-reason__card` は REASON だけ、というように。
- 入れ子を深くせず、クラス1つで要素を指すので、詳細度が上がりません。

### 4-3. CSS の入れ子（ネスト）

素の CSS のネスト機能を使い、**1セクション = 1ブロック**にまとめています。

```css
.p-reason {
	padding-block: var(--space-section);

	& .p-reason__card { … }

	@media (min-width: 768px) {
		& .p-reason__list { … }   /* PC の指定も同じブロックの中 */
	}
}
```

**なぜ入れ子にしたか**

- そのセクションの指定が **PC/SP まとめて1箇所**に集まります。
  「SP の指定はファイル下部の @media にまとまっている」形式だと、
  1つ直すのに2箇所を行き来することになります。
- ブロックの外に出ない限り、他のセクションを壊しません。
- Sass などのビルドが要りません。CSS ファイルをそのまま置くだけで動きます。

**注意**: `&__card` のような文字列連結は素の CSS ではできません
（Sass の機能です）。`& .p-reason__card` とフルネームで書いてください。

### 4-4. カスケード層（`@layer`）

```css
@layer vendor, reset, base, layout, components, sections;
```

**後ろの層ほど強い**というルールで、セレクタの強さ（詳細度）に関係なく
勝ち負けが決まります。

**なぜ必要だったか（実際に起きた事故）**

1. reset の `a { color: inherit }` が `.c-btn--doc { color: … }` より強くなり、
   **CTAボタンの文字が白のまま見えなくなっていた**
2. CDN から読み込む Swiper の CSS は「層の外」に入るため、層に入れた
   こちらの指定より強くなり、**`.p-messages__slide` の `display: grid` が
   打ち消されて写真とコピーの重ねが壊れていた**

1 は reset を層に入れることで、2 は Swiper を `@import … layer(vendor)` で
最弱の層に入れることで解決しています。層が無いと、この手の事故が起きるたびに
`!important` を足すことになります。

### 4-5. 書き方のルール

**1. 高さ・幅を決め打ちしない**

中身と余白（`padding` / `gap`）で決まるようにします。
`height: 696px` のような指定は書きません。文言が1行増えただけで崩れるためです。

**2. 並べるのは flex か grid**

`position: absolute` は**「箱の外へはみ出すあしらい」だけ**です（CI で見張っています）。

| 使っている場所 | 理由 |
| --- | --- |
| `.p-voice__balloon::before/after` | 吹き出しの尻尾。箱の外へ出す三角 |
| `.p-footer__pagetop` | フッターの角に貼り付くボタン |
| `.p-mv__oc` / `__oc-balloon` / `__oc-arrow` | OPEN CAMPUS バッジ一式 |

レイアウトで重ねたい・ずらしたいときは、代わりにこの3つを使います。

| やりたいこと | 使うもの | 例 |
| --- | --- | --- |
| 要素どうしを重ねる | **grid の同じマス**（`grid-area: 1 / 1`） | メインビジュアル / MESSAGES / 「まずは大学を体験してみよう！」 |
| 境目にまたがせる | **マイナスマージン** | `p-reason__title` / `p-courses__rec-label` |
| 端に寄せる | **`justify-self` / `align-self`** | 各セクションの寄せ |

**3. 文字サイズは「固定」と「変化」を分ける**

デザイン上、本文まわりの多くは SP と PC で**同じサイズ**です。
そこを無理に変化させると SP で文字が小さくなりすぎます。

```css
--fs-body:      1rem;   /* 16px 固定 */
--fs-heading:   clamp(1.5rem, 1.3601rem + 0.597vw, 1.875rem);  /* 24 → 30 */
```

`clamp(最小, 推奨, 最大)` は画面幅に応じて滑らかに変える書き方です。
これにより **768px で文字がカクッと変わることがありません**（実測で確認済み）。

**4. 列数は `auto-fit` で幅なりに決める**

```css
grid-template-columns: repeat(auto-fit, minmax(min(100%, 17.5rem), 1fr));
```

「1枚あたり最低◯px」だけ書けば、1列 → 2列 → 3列 と勝手に変わります。
`min(100%, …)` は、画面がそれより狭いときにはみ出さないためです。
**「何px以上なら何列」という指定は書きません。**

**5. スマホとPCの2つだけ。モバイルファースト**

素の指定がスマホ、`@media (min-width: 768px)` が PC です。
`max-width` の `@media` は書きません。
768px で変えるのは「**並びの向きそのものが変わる箇所**」だけです。

- メインビジュアル: 写真の振り分け方
- 学びのカード: 写真が横 ⇄ 縦
- 学生の声: 写真が上 ⇄ 左（吹き出しの尻尾の向きも変わる）
- ボタン / フッター: 縦並び ⇄ 横並び

**6. hover は色の反転。absolute は使わない**

| 場所 | 通常 | hover |
| --- | --- | --- |
| ヘッダー | 塗り + 白文字 | 白地 + 色文字 |
| CTA / まずは大学を体験 | 白地 + 色文字 | 塗り + 白文字 |

色は `--btn-color` 1つにまとめてあるので、そこを変えれば枠線・文字・
反転後の背景がまとめて追従します。
キーボード操作でも同じ見た目になるよう、`:hover` と `:focus-visible` は
必ずセットで書いています。

### 4-6. ハマりやすい落とし穴（実際に踏んだもの）

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| grid の中で要素が横に伸びて横スクロールが出る | grid/flex の子は既定で中身より小さくならない | `min-width: 0` |
| `display: grid` の列が中身の幅まで広がる | 暗黙の列は `auto`（＝中身の最大幅） | `grid-template-columns: minmax(0, 1fr)` |
| grid の `stretch` が効かない | 対象に `margin: auto` が付いている（Swiper など） | `margin-inline: 0` |
| `auto` 列の中で `width: 40%` が決まらず文字が1文字ずつ折り返す | % の基準となる列幅が未確定 | 列幅を `40% 1fr` のように明示 |
| `clamp()` が効かず最小値で固定される | 最小 > 最大 で書いている（エラーにならない） | CI で検算（実装済み） |

## 5. フォント / 外部ライブラリ

- **フォント**: `lp/css/ref001.css` の先頭で Google Fonts から読み込みます
  （Zen Kaku Gothic New / Poppins）。ファイルは同梱していません
- **Swiper**: `lp/js/ref001-interactions.js` が実行時に CDN から読み込みます。
  テーマ側に既に Swiper があればそれを使い、二重読み込みしません

どちらもインターネット接続がある環境でそのまま動きます。

## 6. 確認済みの内容

`php scripts/ci-render-contract.php .` で自動チェックできます。

- 全 PHP の構文チェック
- CSS の相対 `url()` がすべて実ファイルに解決する（素材の入れ忘れ検出）
- 幅で切り替える `@media` が 767/768px の1本だけ（中間ブレークポイントが増えていない）
- `clamp()` の最小値が最大値を超えていない
  （逆に書いてもエラーにならず、黙って最小値で固定されるため）
- `<!DOCTYPE html>` から始まる単独ドキュメントで、`wp_head()` / `wp_footer()`
  が正しい位置にある
- CSS/JS を `add_action` 経由にしていない（発火せず CSS が当たらない事故の防止）
- テンプレートが参照する素材がすべて存在する
- 旧クラス名（`ref-*`）が残っていない
- ACF 未設定時に直書き版と同じ内容が出て、PHP 警告が出ない
- ACF 設定時に内容・件数・画像が実際に切り替わる

### Figma との突き合わせ

Figma REST API でデザインの実データを取得し、実装の計算済みスタイルと
**1項目ずつ機械照合**しています（目視や推測はしていません）。

| | 照合項目数 | 不一致 |
| --- | --- | --- |
| PC 1380px | 43 | **0** |
| SP 375px | 39 | **0** |

照合対象は各テキストの**フォントサイズ・太さ・色**です。
セクションの高さも Figma と一致することを確認しています
（PC: Header 94 / mv 714 / reason 559 / education 684 / cta 328 /
voice 1393 / messages 440 / cources 1514 / links 260 / cta_value 328 / Footer 357）。

**Figma で分かった、見落としやすい指定**

- セクション見出しは1つのテキスト内で大きさが変わる
  （例「千葉経済大学が」30px + 「選ばれる理由」42px）。太さはどちらも 500
- コース見出しだけ **「７」の1文字のみ** 42px / 太さ 900
- 本文まわりの色は `#333` と `#000` を使い分けている
  （見出し・ラベル・カード名 = `#333` / リード文・本文・チェック項目 = `#000`）
- メインビジュアルの人物写真は **570 × 614px**、右側だけ 80px 下げる
- 引用符「“ ”」は明朝体で本文より大きい（SP 100px / PC 119px、本文は 66 / 77px）
